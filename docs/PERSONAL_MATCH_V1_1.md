# Personal Match 1.1 — language, Islamic practice, halal food

Methodology `personal-match-1.1`; profile schema v2. Deterministic, no AI.
Phase 14 (candidates, weights, ranking) and Country Suitability are
untouched.

## The questions (optional, asked after every Phase 14 question)

1. ما مدى أهمية سهولة التواصل بلغة تعرفها أثناء السفر؟ — Very important /
   Important / Not important.
2. (only if 1 is Very important or Important) ما اللغات التي تستطيع
   استخدامها أثناء السفر؟ — multi-select from 17 languages, each an
   official language of at least one catalog country.
3. ما مدى أهمية سهولة ممارسة شعائرك الإسلامية أثناء السفر؟
4. ما مدى أهمية سهولة العثور على طعام حلال في وجهتك؟

3 and 4 are separate, so any combination can be expressed. "Not
important" is neutral: never scored, never a penalty.

The questions are not in `QUESTION_BANKS` and carry no `profileKey`, so the
Phase 14 engine never reads them. `app/src/adaptive/questionnaire.ts` asks
every Phase 14 question first with the unchanged `selectNextQuestion()`,
then the travel needs in order; each Phase 14 path is exactly v1.0's
(`questionnaire.test.ts`, every purpose, with and without location).

## Scoring

Weight = 10 × importance / 100 (Very important = 10, a deciding factor;
Important = 6). The Personal Match formula is unchanged:
`round((Σ wᵢ·fitᵢ + 8·50) / (Σ wᵢ + 8))` over evaluated factors.

| Factor | Evidence | Fit | Not counted when |
|---|---|---|---|
| Language | one of your languages is an **official** language of the country (world-countries data) | 100 | none is official — English, for one, is widely used where it is not official, so this is not evidence of difficulty |
| Islamic practice | mosques / Muslim places of worship **mapped** in OpenStreetMap | ≥ 200, or ≥ 20 at ≥ 5 per 1,000 km²: 100; ≥ 20: 60 | fewer than 20 mapped, or no data for the country |
| Halal food | places **tagged** `diet:halal=yes\|only` in OpenStreetMap | ≥ 20: 100 (one level — see below) | fewer than 20 tagged, or no data |

"Not counted" lowers coverage and confidence, never the score. A travel
need is never a "negative" outcome. Nothing reads religion statistics, an
official religion, a country name or a region, and no country or society
is rated for religiosity. A Muslim-majority country where halal is simply
the default (and rarely tagged) is "not counted", not low; a
non-Muslim-majority country with many tagged places counts. Counts are
national totals, not density near a given hotel — the explanation says
where the number comes from. Halal has a single level on purpose: where
halal is the default it is rarely tagged, so the number of tags cannot
rank one country as "less halal-friendly" than another.

"لماذا هذه النسبة؟" explains each factor in plain words, including what a
"not counted" factor does **not** mean.

## Versioning and migration

- `PERSONAL_MATCH_METHODOLOGY_VERSION = 'personal-match-1.1'`.
- `PROFILE_SCHEMA_VERSION = 2`; migration 1 → 2 keeps every answer, the
  asked order and both timestamps; the new questions start unanswered.
  "Edit my preferences" then asks them.
- Proof that 1.0 did not silently change: a golden fixture generated by
  running the same test against the untouched `wejhaty-v1.0.0` code holds
  digests of every country's full Personal Match (score, coverage,
  confidence, eligibility, every factor) and of the refined top 10 for 112
  profile archetypes. v1.1 reproduces all of them
  (`personalMatch11.golden.test.ts`).

## Privacy

Local only. The answers live in the browser's personalization profile and
are removed by "Reset preferences". They are never sent: no `quiz_answer`
event for these questions, analytics counts exclude them, the admin
catalog and the Worker do not know them, and they never reach a URL, share
text or page metadata (`Quiz.travelNeeds.test.tsx`, `travelNeeds.test.ts`,
and a per-engine production smoke check).
