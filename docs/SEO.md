# SEO and discoverability (v1.1)

Status: CODE-VERIFIED, TEST-VERIFIED; production figures are in
`PROJECT_STATE.md` (state v43). Nothing here fabricates a price, a visa
rule, a safety level, a rating or a "best destination" claim.

## What the build produces

`app/build/seoPages.ts` (a Vite plugin, build only) writes, next to the SPA:

| Output | Count | Notes |
|---|---|---|
| Page documents | 208 | home, explore, 194 destinations (`destination/<id>/index.html`), purpose, 8 quiz purposes, results, favorites, compare |
| `404.html` | 1 | the localized "page not found" document, `noindex` |
| `sitemap.xml` | 196 URLs | home, explore and the 194 destinations — indexable pages only, **no `lastmod`** (no real per-page date exists) |
| `robots.txt` | 1 | allows crawling, points to the sitemap |
| `manifest.webmanifest` | 1 | see "Icons and manifest" |

Every page document is the real app shell (same script, same CSP meta)
with its own head. React boots normally on top of it; there is no
prerendered body and no runtime string replacement. GitHub Pages answers
`/wej/destination/japan/` with HTTP 200 (`/wej/destination/japan`
redirects there with a 301). An unknown path gets the 404 document with
status 404; an unknown destination id renders the same localized
not-found page in the app.

## Route policy

| Class | Routes | robots | canonical / Open Graph / JSON-LD |
|---|---|---|---|
| INDEX | `/`, `/explore/`, `/destination/<id>/` (194) | `index, follow` | yes |
| NOINDEX (utility) | `/purpose/`, `/quiz/<purpose>/`, `/results/`, `/favorites/`, `/compare/` | `noindex, follow` | no — description and robots only |
| NOT FOUND | anything else | `noindex, follow` | no |

Personal and transient application state (quiz answers, results, a
personal match, favorites, a comparison) is never indexable and never in
page metadata.

## One metadata system

- `app/src/seo/meta.ts` — the single source: kind, path, index flag,
  heading, title and description per route, in Arabic and English.
  Destination titles are `<name> للسفر | وجهتي` / `<name> travel | Wejhaty`;
  descriptions come from the editorial description (the 30 full
  destinations) or the region and capital already shown on the card, plus
  one fixed sentence about what the page offers.
- `app/src/seo/document.ts` — renders the head for the static documents:
  escaped title, description, robots, canonical, Open Graph, Twitter card,
  JSON-LD, icons and manifest links.
- `app/src/seo/useDocumentMeta.ts` — applies the same values in the
  running app when the route or the language changes.

## Structured data

- Home: `WebSite`.
- Destinations: `TouristDestination` + `BreadcrumbList`.
- Never: `aggregateRating`, `review`, `offers`, `price` (the build check
  refuses those keys).

## Open Graph image

`public/og/wejhaty-share.png`, 1200×630, generated by
`app/scripts/generate-brand-assets.mjs` from Wejhaty's own brand mark and
wording (no third-party photo), so it is free to use. Destination pages
use the same default image.

## Icons and manifest

`favicon.ico` (16/32 PNG-in-ICO), `icons/icon.svg`,
`icons/apple-touch-icon.png` (180), `icons/icon-192.png`,
`icons/icon-512.png`, `icons/icon-maskable-512.png`. The manifest uses
`start_url` and `scope` = the base path, `display: standalone`, the Light
`theme_color` from `app/src/site/theme.ts`, `lang: ar`, `dir: rtl`.
**No service worker** — a manifest alone does not need one.

## Checks

- `app/src/seo/seo.test.ts` — metadata, escaping, sitemap, robots,
  manifest, JSON-LD keys.
- `app/scripts/verify-seo-build.mjs <dist> [siteUrl]` — 4 804 checks over
  a real build: every document's robots, canonical, OG, Twitter card,
  JSON-LD, unique titles, no local addresses, CSP kept, the sitemap and
  robots, manifest icons, no Israel destination document. Run for both the
  `/wej/` build and a root-domain build.
- `app/scripts/seo-smoke.mjs` — the same checks over HTTP against
  production (`production-smoke.yml`, input `seo_checks`).
