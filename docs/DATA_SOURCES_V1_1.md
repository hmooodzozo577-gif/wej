# Data sources for the v1.1 travel needs

Used only by Personal Match 1.1 (`docs/PERSONAL_MATCH_V1_1.md`), only as
positive evidence. Never used by Phase 14, Country Suitability, the
Passport or any ranking outside Personal Match.

## Official languages — `world-countries`

- Field: `languagesEn` in `app/src/data/generated/countryInfo.json`,
  generated from the `world-countries` package (mledoze/countries data;
  the package's LICENSE file is the ODC Open Database License 1.0).
- Coverage: 195/195 countries have at least one official language
  (the catalog's 194 included).
- What it is: the country's OFFICIAL languages. What it is not: a measure
  of which languages people actually speak with visitors. So a match is
  positive evidence, and no match is "not counted" — never a low score.
- The 17 selectable languages each map to the dataset's own names
  (for example German → German, Swiss German, Austro-Bavarian German;
  Persian → Persian (Farsi), Dari); every option matches at least one
  catalog country (tested).

## Mapped mosques and halal places — OpenStreetMap

- Source: OpenStreetMap contributors, read through the public Overpass
  API. Licence: ODbL 1.0; the committed snapshot
  (`app/src/data/generated/islamicTravelEvidence.json`) is a derived
  database under the same licence.
- Queries (one per country, inside its `admin_level=2` boundary):
  - mosques / Muslim places of worship:
    `nwr["amenity"="place_of_worship"]["religion"="muslim"]`
  - places tagged as serving halal food: `nwr["diet:halal"~"^(yes|only)$"]`
- Pipeline: `app/scripts/lib/islamicTravelIngest.mjs` (pure, tested) and
  `app/scripts/generate-islamic-travel-evidence.mjs` (network; backoff on
  429/503/504, a pause between countries, atomic write only after
  validation: every expected country present once, excluded countries
  refused, counts non-negative integers, at least 80 % with data). A
  missing boundary is "unavailable", never zero.
- Refresh: `.github/workflows/update-islamic-travel-evidence.yml`, monthly
  and on demand; it opens a pull request only when the data changed.

### How the counts are read (thresholds)

| Evidence | Good match (fit 100) | Partial (fit 60) | Not counted |
|---|---|---|---|
| Mosques | ≥ 200 mapped, or ≥ 20 at ≥ 5 per 1,000 km² | ≥ 20 | < 20, or no data |
| Halal | ≥ 20 tagged places | — (no partial level) | < 20, or no data |

Snapshot distribution with these rules: mosques 77 good / 33 partial /
83 not counted / 1 no data; halal 62 good / 131 not counted / 1 no data.

Why halal has no partial level: where halal is simply the default it is
rarely tagged, so the number of tags cannot say that one country is "less
halal-friendly" than another (it would have put Egypt, 97 tagged places,
below France, 2 657). Enough tags is a match; fewer is not counted.

Why mosques also use density: an absolute count alone would call a small
country with many mosques for its size (Brunei, Singapore, Maldives,
Cyprus…) a partial match. The density rule changes only small countries
with at least 20 mapped mosques.

### Known limitations

- Mapping completeness varies by country; counts are national totals, not
  "near your hotel". The explanation always says where the number comes
  from and what "not counted" does not mean.
- Large Muslim-majority countries with under-mapped mosques can read as
  partial rather than good; a partial fit (60) is still above neutral and
  never a penalty.
