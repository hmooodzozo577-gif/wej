# فايب — مرجع التنفيذ وحدود النسخة FIX-10

## الحالة الفعلية
النسخة الحالية تطبيق ويب JavaScript/CSS داخل رابط HTTPS، ويمكن تغليفها في WKWebView. ليست SwiftUI MVVM-C أصلية بعد. هذه الوثيقة تفصل ما نُفّذ عن التصميم المستهدف؛ عدد الأسطر ليس مقياس جودة أو اكتمال.

## ما نُفّذ
- دائرة الملف الشخصي تفتح محرر الصورة: اختيار صورة أو الكاميرا حسب دعم الجهاز، قص مربع أو دائري، تكبير وتحريك بمحاور، اعتماد أو إلغاء، واختيار أفاتار.
- شبكة حتى تسع صور؛ الأولى رئيسية ما لم يُختَر أفاتار مستقل. سحب المقبض لإعادة الترتيب والأسهم بديل متاح. تحرير ومعاينة واعتماد التغييرات.
- 58 سؤالاً عربياً/إنجليزياً في سبع مجموعات؛ ستة اختيارات كحد أقصى، 120 حرفاً للإجابة. الإجابات الفارغة لا تُنشر في الملف.
- الصور المرسلة محلياً تُفتح في عارض يغطي النافذة: تكبير بين 1 و5، قرص بإصبعين، تحريك، أزرار تكبير وتصغير، نقر مزدوج، وسحب عمودي للإغلاق عند 1.
- المايك مستقل عن منتقي الصور. النقر يبدأ ويوقف التسجيل؛ الضغط المطول 350ms يبدأ التسجيل، الإفلات يوقفه، والسحب الأفقي لأكثر من 85px يلغي. الإذن يجب أن يمنحه المستخدم؛ إذا أُفلت الزر قبل اكتمال الإذن يُلغى الطلب المحلي ولا يُحتفظ بالتسجيل المتأخر.
- تسجيل حتى 60 ثانية أو 2MiB. تسجيل فارغ أو زائد الحجم لا يتحول إلى رسالة. مؤقت التسجيل لا يعيد بناء كامل الواجهة كل ثانية.
- ضغط الصور موجود بحد إدخال 5MiB وصيغ JPG/PNG/WebP، إخراج WebP عند دعمه، وتراجع إلى JPEG عند عدم دعمه أو تجاوز الحجم؛ حتى 2MiB، واحتواء داخل 1920×1080 أو 1080×1920 بحسب الاتجاه. Worker مع OffscreenCanvas حيث يتوفر، ومسار Canvas بديل. لا ادعاء بتحقيق HEIC أو نسبة ضغط ثابتة.
- الإنجليزية عند غياب اختيار محفوظ؛ العربية واتجاه RTL متاحان فورياً. الأسئلة مركزية لكن بقية نصوص التطبيق لا تزال ثنائيات داخل دوال العرض ولم تُنقل كلها إلى حزم ترجمة منفصلة.
- شروط التسجيل لا تُطلب في الشات. موافقة التجربة محفوظة محلياً لهذا التثبيت؛ ليست سجلاً موثقاً لحساب في الخادم أو Keychain.

## البنية الأصلية المستهدفة للآيفون — لم تُنفّذ بهذه النسخة
| الطبقة | المسؤولية | الحدود |
|---|---|---|
| Presentation | شاشات SwiftUI، UIKit للوسائط عند الحاجة، حالات عرض وأخطاء | لا اتصال مباشر بقاعدة البيانات |
| Coordinator | رحلة التسجيل، الروابط العميقة، فتح الغرف والعارض | يمرر معرفات دون تخزين أسرار |
| ViewModel | مهام واجهة قابلة للإلغاء على MainActor، اشتقاق حالة العرض | لا ضغط صور أو ترميز ثقيل على MainActor |
| Domain | حالات استخدام إرسال رسالة وقبول شروط وتعديل ملف | واجهات مستقلة عن StoreKit والشبكة |
| Data | مستودعات حساب ورسائل ووسائط، SQLite محمية، عميل API | يحوّل بيانات الخادم إلى نماذج المجال |
| Infrastructure | Keychain، مراقبة الشبكة، التسجيل، معالجة الوسائط | أخطاء typed وقياسات خالية من محتوى الرسائل |

توزيع مقترح: App/Coordinators، Features/{Onboarding,Profile,Chat,Rooms,Settings}، Domain/{Models,UseCases,Repositories}، Data/{Remote,Local,Mappers}، Infrastructure/{Security,Media,Telemetry}.

## هوية الحساب والموافقة
الخدمة الحقيقية تحتاج معرف مستخدم ثابتاً من الخادم. يحفظ سجل قبول termsVersion وprivacyVersion وcommunityVersion وacceptedAt وuserID في الخادم. يحتفظ الجهاز بمرجع آمن عند الحاجة، ولا يثق الخادم بعلم من localStorage. Keychain مخصص للأسرار/المراجع القصيرة؛ قاعدة الرسائل والصور ليست مخزناً مناسباً له. تشفير قاعدة البيانات وحماية الملف وإدارة المفتاح مطلوبة وفق نموذج التهديد.
لا تعيد إجراءات الشات طلب الشروط. حذف بيانات التجربة يعيد موافقتها. انتقال الحساب بين الأجهزة وحذف الحساب غير مطبقين بعد. أذونات الكاميرا والمايك من النظام مستقلة عن شروط التطبيق.

## رسائل Offline-first المستهدفة
كل رسالة لها clientMessageID وserverMessageID وconversationID وsenderID وحالة queued/uploading/sent/failed. يحفظ outbox عملية الإرسال والمعرف قبل الشبكة. الخادم يفرض التفرد بالمعرف لإعادة المحاولة دون تكرار. ترتيب الخادم مرجعي؛ لا يعتمد على ساعة الجهاز.
إعادة المحاولة محدودة مع تأخير متزايد وعشوائية، وإلغاء صريح. بعد إعادة الاتصال تُجلب تغييرات منذ cursor محفوظ. حذف الرسائل يحتاج tombstone وسياسة احتفاظ واضحة. تسجيل الخروج يمسح بيانات الحساب المحلية ومفاتيحه. هذه الخدمات غير متصلة في النموذج الحالي.

## مسار الوسائط المستهدف
اختيار → تحقق نوع وحجم → قراءة أبعاد قبل فك كامل عند الإمكان → downsample مع اتجاه EXIF صحيح → إزالة metadata غير الضرورية → ترميز وفق الجهاز → مصغرة → outbox → رفع مصرح مؤقت → تحقق خادم → إرفاق بالرسالة.
الميزانية المستهدفة الأصلية: احتواء الصورة داخل 1920×1080 أو 1080×1920 حسب الاتجاه دون تشويه. يجب اختبار HEIC/WebP والتراجع لصيغة مدعومة. لا نسبة ضغط ثابتة؛ الصور المضغوطة مسبقاً قد تكبر بالتحويل.
لا تُحذف البيانات فور العرض إذا كان المستهلك يحتاجها. التحرير بعد انتهاء الملكية؛ object URLs عند حذف الوسائط/مغادرة الجلسة، مسارات المايك بعد التوقف، العمال بعد اكتمال العمل. قياس الذروة على صور بانورامية ولقطات عالية الدقة ضروري.

## الخصوصية وتصوير الشاشة
نسخة الويب لا توفر كشفاً موثوقاً للقطات شاشة النظام أو ضمان منع تسجيل الشاشة. لا يوجد هنا تنبيه للطرف الآخر لأن الرسائل محلية أصلاً.
في iOS يُستخدم API العام لحالة التقاط المشهد/الشاشة حسب الحد الأدنى للنظام، مع إخفاء المحتوى عندما تُبلغ حالة التسجيل أو الانعكاس وإيقاف الصوت. يُضاف غطاء انتقال للخلفية لحماية معاينة مبدل التطبيقات. إشعار لقطة الشاشة لا يمكّن التراجع عن الصورة التي التُقطت. لا نستخدم حيل حقول كلمات المرور لإخفاء واجهة كاملة، ولا نعد بخصوصية مطلقة أو منع كاميرا خارجية.

## الصوت الجماعي والخدمات
التسجيل المحلي لا يسجل بقية المتحدثين. الغرف الحقيقية تحتاج خدمة WebRTC/SFU ورموز دخول قصيرة الأجل من الخادم، وقواعد مضيف/متحدث/مستمع، وموافقة واضحة على تسجيل الروم. السينما المتزامنة تحتاج مرجع وقت وحالة تشغيل مشتركة وحقوق محتوى. الدعم الذكي والإبلاغ والدفع تحتاج خدمات وتحققاً منفصلين. لا مفاتيح API داخل HTML أو Swift bundle.

## الأداء والتوافق
لا ضمان Zero Frame Drop أو Crash Elimination. القياس المطلوب: زمن فتح الشاشات وp95 لتجهيز الوسائط، الذاكرة القصوى، انقطاع الشبكة، رفض/سحب الأذونات، الخلفية، الضغط المتكرر، الصور التالفة، تدوير الجهاز، تكبير النص، لوحة مفاتيح عربية/إنجليزية. استهداف 60/120 إطاراً يتبع الجهاز وظروفه ولا يتحول إلى وعد ثابت.
Safe Areas في الويب عبر viewport-fit وenv؛ SwiftUI يستخدم safeAreaInset وإدارة لوحة المفاتيح الأصلية. لا يُجمع تعويض لوحة المفاتيح اليدوي مع تعويض أصلي دون قياس لتجنب الإزاحة المزدوجة.

## التحقق لهذا التغيير
فحص JavaScript واختبارات VM لمنطق الصفحات والترجمة وحد الستة أسئلة والهروب من المدخلات وإدارة الحالة. اختبارات الدعم بمحاكاة OpenAI. لا اختبار جهاز iOS أو Xcode أو لمس حقيقي أو رفع إلى خادم؛ يلزم ذلك قبل إصدار إنتاجي.

## FIX-11 — روابط الفيديو واستجابة العرض
يعرض الشات آخر 30 رسالة أولاً مع تحميل أقدم محلياً. لا توجد شبكة رسائل حقيقية تحتاج prefetch بعد؛ لا ادعاء باستجابة 4ms. زر التبويب الحالي لا يعيد بناء الصفحة. الخلفية الضبابية منفصلة عن الصورة الأمامية؛ عارض Canvas يستخدم كثافة بكسلات الجهاز حتى 3 مع إبقاء حد الذاكرة مضبوطاً.
يوتيوب: عنوان عبر oEmbed ثابت المضيف، معرف 11 محرفاً، مهلة 4 ثوانٍ وحد استجابة 16KB. لا يُجلب HTML مضمّن من المصدر ولا تُجلب عناوين URL عشوائية على الخادم. فشل البيانات يبقي بطاقة YouTube العامة. الغلاف من i.ytimg.com؛ المشغل من youtube-nocookie.com بعد النقر. لا تتوفر بيانات وصفية تلقائية لكل منصة.
روابط HTTPS التي تنتهي MP4/WebM/M4V تفتح في video داخل الشات حسب دعم الترميز والخادم. المواقع الأخرى لها رابط مصدر. المشغل يختار جودة يوتيوب، والملف المباشر ليس بثاً متعدد الجودات؛ لا ضمان 4K أو تشغيل دون تقطيع. قد يمنع المصدر التضمين أو يحتاج تسجيل دخول. معاينات وروابط الفيديو تتصل بخدمات خارجية كما يوضح إشعار الخصوصية.
حماية تصوير الشاشة لم تتغير: لا كشف نظامي موثوق أو منع مطلق في الويب، ولا تنبيه للطرف الآخر في نموذج محلي.
المصدر: https://developers.google.com/youtube/player_parameters

## مراجعة الأقسام السبعة — FIX-12
1. التنقل: ما زالت البيانات التجريبية في الذاكرة منذ فتح الصفحة؛ لا تُختلق طلبات شبكة بغرض prefetch. آخر 30 رسالة أولاً، تخفيف النقر المكرر، تأجيل بيانات الفيديو لمهمة لاحقة، وإلغاء الطلبات القديمة عند الانتقال. لم يُنفذ مخزن خلايا أصلي أو تشفير رسائل خلفي، ولم تُقَس استجابة 4ms.
2. الصورة: مسار تجهيز مستقل للأفاتار بصيغة PNG قبل القص لتجنب ضغط JPEG/WebP السابق، حتى 2048 في البعد الأطول و16MiB للمؤقت، مع تسلسل عملية واحدة ومؤشر تجهيز. القص النهائي 512px. الصورة الأمامية بلا blur؛ الخلفية طبقة منفصلة مع تعتيم. يمنع عارض الصور إعادة تخصيص Canvas بلا تغير الحجم. لا يستعيد هذا تفاصيل صورة أصلها منخفض الجودة.
3. الشات والعارض: أزرار مستقلة ومؤقت ضغط مطول يُلغى مع الإيقاف/التنقل/الخلفية. إخفاء الأزرار عند الكتابة موجود. العارض 1–5x. تصوير النظام لا يُمنع ولا يُرسل تنبيه للطرف الآخر في هذه النسخة؛ لا نضع غطاء شكلياً يوحي بذلك.
4. الفيديو: عناوين YouTube مجدولة دون انتظار التنقل، ذاكرة عميل 100 عنصر ومحاولات فشل مؤجلة 30 ثانية، وطلبات قابلة للإلغاء بمهلة 5 ثوان. خادم: cache حتى 100 عنوان لخمس دقائق و20 طلباً غير مخدوم من cache بالدقيقة لكل عنوان اتصال كما تعطيه منصة الاستضافة، وخريطة عدادات محدودة 500. القيود محلية لعازل Worker وليست ضماناً موزعاً. إعادة الرسم أثناء تشغيل المشغل قد تعيد إنشاءه؛ المحافظة على المشغل بين كل أنواع تحديثات الشات تحتاج فصل عرض أكبر لاحقاً. لا تشغيل مضمون لكل منصة أو 4K.
5. الذاكرة: تنظيف مشغل الروابط ومصادر الفيديو عند الخلفية/المغادرة، إلغاء جلب العناوين، منع تجهيز أفاتارات متزامنة، وإزالة مؤقتات الضغط. ضغط صور الشات عبر Worker حيث يدعم الجهاز؛ Canvas البديل والأفاتار ليسا pipeline أصلياً بالكامل في خيوط iOS.
6. اللغات: الإنجليزية أولاً ما لم تحفظ العربية سابقاً؛ التبديل فوري وRTL/LTR. لا تغيير اختيار مستخدم محفوظ عند التحديث.
7. الموافقة: محفوظة للتثبيت التجريبي ولا يطلبها الشات؛ فحص إعادة الدخول مع قبول محفوظ مضاف. مسح البيانات يعيد الإعداد؛ الموافقة المرتبطة بالحساب الحقيقي وKeychain مؤجلتان لربط الحساب ونسخة iOS.

التحقق: اختبارات VM للمنطق واللغات والموافقة وإلغاء مؤقت المايك والطلبات وتنظيف bitmap، واختبار endpoint الفيديو بupstream محاكى وcache. اجتاز بناء Worker. لا اختبار Safari فعلي، أو Xcode، أو جهاز آيفون، أو بث خارجي حي. المخرجات لا تُعد شهادة خلو من crash أو تدقيقاً أمنياً شاملاً.


## FIX-13 — سينما مشتركة متعددة الأجهزة
- المسار `/cinema.html` يتيح لصق رابط يوتيوب أو MP4/WebM/M4V، وإنشاء جلسة D1 ورابط دعوة صالح 24 ساعة. روابط الفيديو والمشاهدات لا ترفع ملفات المستخدم.
- المعرف عشوائي 192 بت للانضمام. رمز تحكم مستقل للمضيف يُخزن بصورته المجزأة SHA-256 في D1 ويُرسل حصراً في Authorization؛ النسخة الأصلية تبقى بذاكرة صفحة المضيف. إعادة تحميل الصفحة تفقد تحكم المضيف وتدخل كضيف.
- تحديثات المضيف: تشغيل، إيقاف، تغيير المقطع، والتقديم؛ `version` يمنع الكتابات المتأخرة. الضيوف يقرؤون الحالة كل ثانيتين (8 عند إخفاء الصفحة)، ويُحسب الموضع باستخدام توقيت الخادم ومرجع monotonic بالمتصفح، ويُصحح الانحراف فوق ثانيتين.
- مزامنة تقريبية وليست ضماناً لكل إطار؛ إعلان يوتيوب، buffering، تقييد التضمين، وإذن autoplay قد يؤخرون جهازاً. المضيف لا يتحكم بتجاوز الإعلانات أو سياسات المصدر.
- الأشخاص السابقون بالرومات بيانات تجريبية. المشاركة الحقيقية هنا عبر رابط جلسة السينما فقط، وليست خدمة غرف صوتية أو حسابات اجتماعية متكاملة.
- الجلسات المنتهية غير قابلة للقراءة؛ الحذف الفعلي عند إنهاء المضيف أو عند تنظيفها أثناء إنشاء جلسة لاحقة. لا يوجد cron مدّعى.
- اختبارات API تستخدم SQLite فعلية ومحول D1 محلي للتحقق من مشاركة الحالة، عزل تحكم الضيف، التعارض والحذف. لم تُجرَ تجربة بجهازي آيفون أو اختبار فيديو فعلي.


## FIX-14 — الحساب وPremium والإرسال المباشر
- زر Premium ذهبي في الزاوية المنطقية العلوية للملف الشخصي يفتح العرض. الشهرية مخططة بـ20 ر.س، السنوية دون سعر محدد، ومدى الحياة قيد الدراسة؛ لا دفع حقيقي.
- قوائم السياسات والأمان والدعم مركزية داخل الحساب، دون تذييل متكرر بالشاشات العامة. روابط الموافقة في التسجيل وأدوات البلاغ السياقية محفوظة.
- انتهاء تسجيل الصوت (رفع الإصبع بعد الضغط المطول أو زر الإيقاف أو بلوغ الحد) يضيفه تلقائياً للشات المحلي. السحب والإلغاء ومغادرة الصفحة أثناء طلب الإذن لا ترسل تسجيلاً.
- الصورة تُضغط ثم تضاف مباشرة دون معاينة؛ حدود الملفات والذاكرة مستمرة. لا رفع لشات حقيقي ولا ادعاء تسليم للغير.
- الاهتزاز best-effort عبر navigator.vibrate إن دعمه الجهاز، وليس تكاملاً لمسياً أصلياً مع iOS.
- اختبارات وظيفية بمحاكاة التسجيل: الصوت عند الرفع، الإلغاء دون إرسال، والصور بلا تأكيد، ومركزية قائمة الحساب. لا اختبار على آيفون فعلي.
